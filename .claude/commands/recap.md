# やり残し棚卸し（Recap）

数日前のセッションが切れて、そのまま忘れている作業を掘り起こすコマンド。
Web版のセッションは会話ログを保持しないので、**各セッションが残したブランチ・PR・コミット・
レビューコメントを「過去セッションの指紋」として使い**、「何を・いつ・どこまでやって放置したか」を
再構成してユーザーに思い出させる。

目的は「PRを作る/レビューする」ことではなく、**忘れている作業を思い出させること**。
だからレポートは「タスク一覧」ではなく「◯日前に△△をやりかけて止まっている」という思い出し口調で書く。

## 引数

`$ARGUMENTS`

- 数値（例 `2`）… 「何日以上動いていないもの」を放置とみなすしきい値（省略時は **1日**）
- `all` … マージ済み・クローズ済みも含めて棚卸し
- それ以外の自由文 … レポートの最後に従う追加指示（例: `Slackの#dailyに投稿` / `tarokyog@gmail.com にメールで送る`）

## やること

今日の日付を基準に、以下を調べる。GitHubは `mcp__github__*` ツール、ローカルgitは Bash を使う。
対象リポジトリは `joucomi/joucomi`。`mcp__github__get_me` で自分のユーザー名を確認してから絞り込む。

### 1. 放置されたブランチ（最重要 = やり残しの本体）
- `git fetch --all --prune` の後、`git for-each-ref --sort=-committerdate refs/remotes/origin` で
  全リモートブランチを最終コミット日順に取得。
- `main`（既定ブランチ）にマージ済みのブランチは除外（`git branch -r --merged origin/main`）。
- 残った未マージブランチそれぞれについて:
  - 最終コミット日 → 「何日前に止まったか」
  - 直近2〜3件のコミット件名 → 「何をやっていたか」
  - 対応する **開いているPRがあるか**（`mcp__github__list_pull_requests` / `search_pull_requests`）
  - PRが無いブランチ＝「プッシュしたきりPRも作らず放置」→ 特に拾う

### 2. 自分の開いているPRで止まっているもの
- `mcp__github__list_pull_requests`（state=open）で自分が作者のPRを取得。
- それぞれ:
  - **CIの状態**（`mcp__github__pull_request_read` で status / checks）。失敗のまま放置を拾う。
  - **未返信のレビューコメント**（＝文字どおりの「返信忘れ」）。レビューコメントが付いているのに
    自分が最後に反応していないものを拾う。
  - 最終更新からの経過日数。
  - ドラフトのまま長期放置されているもの。

### 3. 自分宛で止まっているIssue（あれば）
- `mcp__github__list_issues` / `search_issues` で自分がアサインされた open Issue。
- コメントが付いて返信待ちのまま放置されているものを拾う。

## しきい値

`$ARGUMENTS` に数値があればその日数、なければ **最終アクティビティが1日以上前** のものを「放置」とみなす。
当日動いたものは「いま作業中」とみなしてレポートから外す（うるさくしない）。

## 出力フォーマット

日本語で、思い出させる口調。優先度順（古い・CI失敗・返信待ちを上に）。各項目に必ず
**「再開のひとこと」**（そのままコピペでセッションに貼れる指示）を添える。

```
☀️ やり残し棚卸し（2026-06-11 時点）

🔴 返信・対応待ち（急ぎめ）
• [PR #12] ログイン処理のリファクタ — 3日前にレビューコメントが付いたまま未返信
    └ 内容: 〇〇という指摘。CIは通っている。
    └ 再開のひとこと:「PR #12 のレビューコメントに対応して」

🟡 放置中のやり残し
• [branch claude/foo-x9] 検索APIの実装 — 2日前のコミットで停止、PR未作成
    └ 直近コミット: "WIP: add search endpoint"
    └ 再開のひとこと:「ブランチ claude/foo-x9 の続きをやって。検索APIの実装の途中」
• [PR #9(draft)] 設定画面 — 4日前からドラフトのまま、CIが赤
    └ 再開のひとこと:「PR #9 のCIを直してレビューに出せる状態にして」

🟢 様子見（参考）
• [branch claude/bar-z2] 1日前に停止。まだ新しいので保留でOK。

―― 合計: 対応待ち1 / 放置2 / 様子見1
```

該当が無ければ「✅ 放置されているやり残しはありません。クリーンです」と一言で返す。

`$ARGUMENTS` に配信先の自由文（Slack / メール 等）が含まれていれば、レポート生成後に
その指示に従って配信する（Slackは `mcp__Slack__*`、メールは `mcp__Gmail__*` 連携を使う）。
配信先指定が無ければチャットに表示するだけでよい。

## 注意
- 読み取り中心。勝手にコミット・PR作成・マージ・クローズはしない（ユーザーが再開を指示したら別）。
- ブランチ名・PRタイトル・コミット件名から「何の作業だったか」を必ず一言で補い、思い出しやすくする。
